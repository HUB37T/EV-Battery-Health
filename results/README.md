# Results

Everything in this folder is generated by code (`python -m ev_battery <stage>`).
Never edit numbers by hand. Each stage has one Markdown report as its entry point.

| Folder | Report | Main contents |
|---|---|---|
| `audit/` | [AUDIT_REPORT.md](audit/AUDIT_REPORT.md) | Schema, quality, target leakage, split |
| `eda/` | [EDA_REPORT.md](eda/EDA_REPORT.md) | 18 train-only figures and supporting tables |
| `preprocessing/` | [PREPROCESSING_REPORT.md](preprocessing/PREPROCESSING_REPORT.md) | Three recipes, train-fitted parameters, integrity checks |
| `experiments/` | [EXPERIMENT_REPORT.md](experiments/EXPERIMENT_REPORT.md) | Staged MLP study, learning curves, epoch budget, seed confirmation |
| `feature_engineering/` | [FEATURE_ENGINEERING_REPORT.md](feature_engineering/FEATURE_ENGINEERING_REPORT.md) | Domain feature ablation on validation |
| `final_evaluation/` | [FINAL_REPORT.md](final_evaluation/FINAL_REPORT.md) | Locked test scores, errors per SOH band and per battery |

`experiments/runs/<run_id>/` stores `config.json`, `history.csv` (per-epoch
metrics) and `summary.json` for every run, including losing runs. They are
summarised in `experiments/run_summary.csv`.

Row-level predictions are not committed because they are large and reproducible:
per-run validation predictions and `final_evaluation/predictions/`.

Reporting rule: test metrics exist only for configurations locked in
`final_evaluation/evaluation_lock.json` before scoring. Every seed is reported,
and there is no seed selection or tuning on test.
